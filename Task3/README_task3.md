# Оценка шифрования данных в режиме "данные лежат" и "данные передаются"

## 1. Назначение и охват
Документ задаёт сквозную стратегию защиты данных платформы «Медикаменте» с учётом **состояния** данных (хранение / передача / использование). Опирается на реестр конфиденциальных данных и проблемные зоны из Task 1 (в частности **P-02** — нет шифрования at-rest, **P-03** — нет шифрования передачи) и на блоки Privacy by Design из Task 2 (Vault/KMS, маскирование, ABAC, аудит).

## 2. Модель классификации (по нескольким параметрам)
Каждый класс данных оценивается по измерениям, от которых зависит выбор метода защиты:
- **Состояние:** at rest (хранение) · in transit (передача) · in use (обработка).
- **Уровень чувствительности:** `Public` · `Internal` · `Confidential` · `Restricted` (спец. категория ПДн).
- **Категория:** `PII` · `PHI` (медицинские, ст. 10 152-ФЗ) · `FIN` · `EMPLOYEE` · `SECRET` (учётные данные/ключи).
- **Профиль риска:** влияние (ущерб при утечке) × вероятность (доступность для атаки) → `Низкий` / `Средний` / `Высокий` / `Критический`.
- **Доп. параметры:** правовое основание (спец. категория), объём/охват, требование обратимости (нужна ли расшифровка для операций).

## 5. Базовые средства защиты — шифрование at rest
Базовая (обязательная) реализация хранения:
- **Том/диск:** LUKS/dm-crypt на серверах Linux; для рабочих станций — SED-диски с привязкой ключа к **TPM**.
- **База данных (PostgreSQL):** field-level шифрование (pgcrypto / Vault transit) для спец. категории и реквизитов; шифрование тома под кластером; TLS для подключений.
- **Аналитика (ClickHouse):** шифрование данных at-rest; только обезличенные данные.
- **Файлы/объекты:** объектное хранилище с серверным шифрованием (SSE), напр. MinIO; шифрование вложений.
- **Резервные копии:** шифрование с отдельными ключами, хранение в РФ.
- **Управление ключами:** **HashiCorp Vault / KMS + HSM**; ротация ключей, разделение обязанностей (split knowledge), crypto-shredding (уничтожение данных удалением ключа).
- **Сертифицированная криптография:** для спец. категории ПДн — сертифицированные ФСБ **СКЗИ на ГОСТ** (CryptoPro CSP / ViPNet); уровень защищённости ИСПДн определяется по **ПП-1119**, меры — по приказам **ФСТЭК/ФСБ**.

## 6. Базовые средства защиты — шифрование in transit
- **Внешний периметр:** **TLS 1.3** на API Gateway, HSTS, современные наборы шифров; ГОСТ-TLS на каналах со спец. категорией.
- **Между сервисами:** **mTLS** через service mesh в Kubernetes — взаимная аутентификация по сертификатам.
- **Между филиалами:** **ГОСТ-VPN** (С-Терра / ViPNet / Континент), IPSec site-to-site.
- **Почта:** SMTP over TLS + DLP; запрет пересылки спец. категории по незащищённой почте.
- **Интеграции (лаборатория, банк, 1С, ККМ):** только по TLS; контракты скрывают спец. категории; object-level authz.
- **Управление сертификатами:** внутренний УЦ + **cert-manager**; мониторинг истечения, запрет слабых шифров и нешифрованных эндпоинтов.

## 7. Защита in use (кратко)
Токенизация (Vault transit), динамическое маскирование (**pg-anon**) по ролям, минимизация данных в памяти и логах; при необходимости — конфиденциальные вычисления.

## 10. Соответствие требованиям и закрытие проблем
- **152-ФЗ + ПП-1119:** определение уровня защищённости ИСПДн; для спец. категории — повышенные меры и сертифицированные СКЗИ (ФСБ), меры защиты — по приказам **ФСТЭК** № 21 и **ФСБ**.
- **ГОСТ:** Р 34.12-2018 (шифрование «Кузнечик»/«Магма»), Р 34.10-2012 (ЭП), Р 34.11-2012 (хеш «Стрибог»).
- **Закрывает из Task 1:** P-02 (шифрование at-rest), P-03 (шифрование передачи), частично P-05 (аудит дешифрования), P-10 (шифрованные бэкапы в РФ), P-13 (контроль скрытых копий).

> Принцип стратегии: шифрование — не одна мера, а **слои** (диск → том → поле → канал → ключи), управляемые тегами и автоматическим контролем. Большая часть базовых средств уже есть в стеке компании (Vault, PostgreSQL, ClickHouse, Elastic, Victoria Metrics, Kubernetes); добавляются преимущественно аппаратные средства (HSM, токены, криптошлюзы для филиалов) и сертифицированные СКЗИ.
