# Проблемные зоны безопасности данных «Медикаменте» (As-Is)
*Task 1 — аудит мер по обеспечению безопасности данных*

## 1. Метод аудита
Каждый бизнес-процесс разобран на элементы потока данных (по нотации DFD): **внешние сущности → процессы → хранилища → потоки**. Для каждого элемента проверено соответствие принципам **Privacy by Design**, **Data Minimization**, **Data Lineage** и триаде **CIA** (конфиденциальность, целостность, доступность), а также требованиям **152-ФЗ**.

## 3. Выводы по принципам
- **Privacy by Design — отсутствует.** Защита не встроена: нет приватности по умолчанию, доступ не ограничен, данные не классифицированы.
- **Data Minimization — нарушена.** Собираются избыточные поля, плодятся копии (Excel-дубли, бэкапы, выгрузки), ПДн дублируются в именах объектов.
- **Data Lineage — отсутствует.** Потоки данных не контролируются и не задокументированы; нет реестра обработки.
- **CIA:** конфиденциальность — нет шифрования / контроля доступа / аудита; целостность — двойной ручной учёт и ручные правки; доступность — единая точка отказа без резерва.

## 4. Приоритеты устранения (что улучшить в первую очередь)
1. 🔴 Убрать ПДн из имён файлов/папок → суррогатные идентификаторы (P-01).
2. 🔴 Включить шифрование at-rest и контроль доступа RBAC/ABAC (P-02, P-04).
3. 🔴 Внедрить аудит доступа и мониторинг/алертинг (P-05).
4. 🔴 Обеспечить удаление по запросу и retention-политики (P-11).
5. 🟠 Развести данные по доменам и контурам, ввести классификацию/тегирование (P-06, P-15).
6. 🟠 Перевести аналитику на обезличенные данные (P-09).
7. 🟠 Задокументировать потоки (Lineage) и реестр обработки ПДн (P-12).
